## Per-module verdicts

1. **`SeoPageShell`** — **tune** — `page-shell.tsx:156-162`. The API is close to complete; the one gap is real and two families have already routed around it. The footnote renders as a `<p>`, so nothing block-level can go in it: `companies.tsx:135-153` inlines a raw `<a>` because "`LogoDevAttribution` is a `<div>` and the shell's footnote is a `<p>`", and both broker pages render `BrokerComplianceNote` in a hand-rolled `<div className="border-t … pb-16 pt-6">` *outside* `</SeoPageShell>` (`broker-category.tsx:282-284`, `broker-comparison.tsx:390-392`) — duplicating the shell's own ruled-footnote treatment. Fix: make the footnote a `<div>` carrying the same type classes, and let `footnote` accept a block. That deletes all three workarounds.
2. **`SeoPageShell` — notice slot width** — **tune** — `page-shell.tsx:137`. The slot is hard-capped at `max-w-[62ch]`, which is right for a caveat line and wrong for the two `width="wide"` broker pages, where the `BrokerDisclosure` box (`broker-ui.tsx:305-317`) is a bordered strip that now stops short of the content it's disclosing. Either drop the cap when `width === "wide"` or expose `noticeWidth`.
3. **`SeoPageShell` — doc comment** — **tune** — `page-shell.tsx:70-72`. It states "`/compare` is the one sanctioned case" for omitting the CTA. `/compare` doesn't use the shell at all, and `/brokers/compare/:pair` **does** pass a CTA (`broker-comparison.tsx:250-255`). The comment describes a decision no code implements. The only real `cta={false}` is the invalid-year board (`biggest-buys.tsx:237`), which is correct and unmentioned.
4. **`SeoSkeleton`** — **tune** — `skeletons.tsx:49-50`. Every instance renders its own `aria-busy` wrapper and its own `<span className="sr-only">Loading…</span>`, and three pages stack two or three instances (`sector.tsx:216-222`, `biggest-buys.tsx:301-306`, `report.tsx:209-214`) — so a screen reader hears "Loading…" two or three times for one page state. Fix: move the wrapper to the shell (it already owns the `loading` flag) and make `SeoSkeleton` render a bare fragment.
5. **`SeoSkeleton` — variant coverage** — **tune** — `skeletons.tsx:18-23`. Two genuine gaps, both currently filled by hand-rolled markup: (a) a **media list** — a ruled row with a logo bubble, which is what `/learn`'s `LiveExamples` draws by hand (`learn.tsx:383-399`) and what `/sectors/:slug`'s two lists actually look like; `ruled-list` has no avatar slot and `ranked-board` carries a rank gutter those rows don't have. (b) a **columned index** for `/companies`. A third, `doc-sections`, exists but the broker pages don't use it — `broker-category.tsx:454` and `skeletons.tsx:104` contain the *same* `grid gap-x-10 … sm:grid-cols-[10rem_minmax(0,1fr)] sm:py-9` string, copied. The broker skeletons are otherwise well-shaped and worth keeping bespoke; they should at least compose `doc-sections` for the ruled part.
6. **`SeoSkeleton` — call sites** — **tune** — `sectors.tsx:127`, `reports.tsx:149`, `companies.tsx:155`. See the refuted claim above. `sectors.tsx` is a one-line fix (`<SeoSkeleton rows={4} variant="stat-tiles" />` ahead of the list, as `sector.tsx:217` already does).
7. **`SeoSection`** — **keep** — `section.tsx:18-67`. Both variants are correct, `scroll-mt-24` is set on both so the `#methodology` / `#verdict` anchors clear the navbar, and `PageSection` (`broker-page-ui.tsx:55-71`) is a thin re-export that keeps the `/brokers` import path stable. No page fights it. Nothing to do.
8. **`RelatedCards`** — **keep** — `related-cards.tsx:29-66`. Right object, right hover/focus treatment, tokenised throughout (`border-hairline`, `bg-sheet`, `ring-brand-brown/40`). One cosmetic note, not worth a change on its own: `cols={4}` forces `grid-cols-2` on mobile (`:26`) where `2` and `3` fall back to one column — so the four-up rail is the only card grid that goes two-up on a phone. Intentional-looking; leaving it.
9. **`StatTiles`** — **keep** — `stat-tiles.tsx:31-85`. The borderless tint well matches the company page it was extracted from, `tone` maps to `text-positive`/`text-negative` (`:66-70`) with no local greens anywhere, and the `cols` doc (`:41-44`) is the sort of instruction that stops the next 5-stat group going ragged. `SectorFigures` (`sector-ui.tsx:229-258`) and `MonthlyMetrics` both consume it correctly.
10. **`AppCtaBand`** — **keep** — `app-cta-band.tsx:44-147`. Fully tokenised (`bg-ink`, `text-brand-amber`, `text-ink` on the white button), headline is a `<p>` not a heading so the document outline stays about the topic (`:98`), the screenshot column is `lg:` only so mobile doesn't get a phone under the button that installs it (`:120-124`), and the QR branch correctly renders nothing on touch (`:76-77`). Worth recording: the screenshot assets **do** now exist — `public/app-shots/{uk,us}/{ios,android}/{analysis,cluster,recap,today}.png` are all present, so every `screenshotSlot` in use resolves to a real capture rather than a placeholder. (`CLAUDE.md`'s "App screenshots don't exist yet" is stale.)
11. **`cta-copy.ts`** — **tune** — `cta-copy.ts:28,35,47,66,79`. Bodies no longer converge on one sentence but they converge on one *ending*. Cut the trailing "rated / with the thesis attached" clause from three of the five that carry it and let each body end on its own claim; `learnCta` and `companiesCta` also need their middle claims separated ("spots it for you" vs "checks it for you" is the same promise).
12. **`SeoRail` — token violations** — **tune** — `seo-rail.tsx:99,100,107,121`. This is the shared-furniture token breach the brief asked about, and it's the widest-blast-radius one: seven page families import this component. `#e8e0d5` → `border-hairline`, `#faf7f2` → `bg-sheet`, and `bg-[#1a140d] … hover:bg-[#2a2118] dark:bg-white dark:text-[#1a140d] dark:hover:bg-white/90` (`:121`) is a character-for-character re-implementation of `BUTTON_FILLED` (`button.ts:30-31`) — in a file that already imports `BUTTON_RADIUS` from that module. `globals.css:32-42` explicitly says "prefer the utility forms … over new bracketed literals". Nothing else in `src/components/seo/` has a raw hex.
13. **`SeoRail` — self-link filter** — **tune** — `seo-rail.tsx:93-96`. `pathname.startsWith(href)` is too loose for the `/us` market home: on `/us/directors/:id` (a real route, `App.tsx:55`) `"/us/directors/123".startsWith("/us")` is true, so the rail drops "Latest filings" on a page that isn't the market home. Compare against the resolved path, not a prefix.
14. **`SeoRail` — cross-market links** — **tune** — `seo-rail.tsx:87-91`. `MARKET_HOME` is market-aware but the other four links are hardcoded UK-absolute. On `ddbx.eu` (`/se|/nl/directors/:id`) the rail offers Companies / Sectors / Biggest buys, all four of which the edge 301s to `ddbx.uk` (`shared/seo.js:129-147`). Filter them out when the market isn't `uk`/`us`.
15. **`SeoRail` — internal nav** — **tune** — `seo-rail.tsx:135-138`. Plain `<a href>` inside a React Router app: every rail click is a full document reload, and the rail is the SPA's only navigation that does this. Should be `<Link to>` (the component already imports from `react-router-dom`).
16. **`MeterBar`** — **keep** — `meter-bar.tsx:15-44`. Correct in every dimension I can test it on: `aria-hidden` with the number beside it as the accessible value, `min(100)` clamp, the `max(2px, …)` floor so a 0.4% row still marks, brand token pair with a dark half, and a genuine zero renders as nothing rather than as 2px of false signal. The uplift doc's `tone` prop was never built; no caller wants it. Leave it.
17. **`TrackingNotice`** — **move** — `tracking-notice.tsx:18-33`. The component is right; its home is wrong. The sentence and the year live in `src/`, which the Functions can't import, so both are hand-copied into `functions/reports/index.js:124`, `functions/biggest-buys/[[route]].js:105` and `shared/leaderboard.js:46` — and the sector pre-renders, which never got the copy, publish the twelve-month framing to crawlers with no caveat while the React pages show one. Move `TRACKING_SINCE_YEAR` / `TRACKING_SINCE_LABEL` / the sentence into `shared/`, import from all five sites.
18. **`functions/_middleware.js` skip list** — **keep** — `_middleware.js:91-107`. Every route with a pre-render Function is on it, and the comment at `:82-90` explains the non-obvious reason (tags are appended, not rewritten, so two passes emit two canonicals). The `/us/t/` omission is safe because that Function returns a 302 with no HTML.
19. **`src/components/button.ts`** — **keep** — nothing in the SEO tree misuses it. `app-cta-band.tsx:108` correctly declines `BUTTON_FILLED` (near-black on a near-black band) and says so in a comment; `reports.tsx:261` uses `BUTTON_FILLED` + `BUTTON_RADIUS` properly. Only `seo-rail.tsx:121` re-implements it — counted in item 12.
20. **Cross-family: standfirst weight** — **tune** — `page-shell.tsx:125-135`. Half the family opens at `lede` (16.5/85: learn index, learn entry, both broker guides, `/reports/:month`) and half at `body` (14/70: sectors, sector, biggest-buys, reports index, companies). The document-vs-list split is defensible but it isn't written down anywhere, so the next page will pick by coin toss. One sentence in the prop doc fixes it.
21. **Cross-family: `gaLabel` convention** — **tune** — `report.tsx:159` and `:201`. Every other family uses `Family · key` (`Sector · health-care`, `Learn · closed-period`, `Broker guide · best-isa`). Both report branches pass the bare string `"Monthly report"`, so all twelve months a year and the not-found state report as one label, and the archive-index → month funnel can't be measured.
22. **Cross-family: `LogoDevAttribution` placement** — **tune**. Four families put the same attribution in four places: inside the methodology section (`biggest-buys.tsx:491`), inside the examples section (`learn.tsx:412`), as a trailing child *above* the CTA band (`sector.tsx:375`), and inlined into the footnote below it (`companies.tsx:141-151`). ## Bugs (correctness / compliance / parity)

1. **UK affiliate rail served on `ddbx.eu`.** `learn.tsx:134`, `:174`, `:206` choose the rail market with `owner === "us" ? "us" : "uk"`. `ownerForHost` returns `null` on `ddbx.eu` (`shared/glossary.js:375-384`), so `/learn` and every `/learn/:slug` on that host renders `BrokerAside` — FCA-regulated UK broker affiliate links, plus "Start investing", to a Swedish or Dutch reader who cannot open those accounts. The four sibling research routes are edge-redirected off `.eu` for exactly this class of reason (`shared/seo.js:113-134`); `/learn` deliberately isn't, because the glossary genuinely serves those readers. Fix in the page, not the redirect list: resolve the rail's market from the host (`marketForPath`), independently of which host owns the entry.
2. **Sector pre-renders omit the tracking caveat.** `sectors.tsx:116` and `sector.tsx:207` render `TrackingNotice`; `functions/sectors/index.js` and `functions/sectors/[slug].js` don't. The pre-render states "rolling twelve months of disclosed purchases" (`functions/sectors/index.js:94`) as an unqualified claim about a period we only have five months of. Parity runs the safe direction here — the reader gets more, not less — but the crawler-visible copy is the one making an overstated factual claim.
3. **`CONTENTS` duplicated across the parity boundary.** `functions/reports/index.js:74-95` vs `reports.tsx:47-73`, five paragraphs, kept in step by a comment. This is most of `/reports`' crawlable prose. Move to `shared/`.
4. **Rail drops the market-home link on `/us/directors/:id`.** `seo-rail.tsx:93-96` — prefix match, described in item 13.
5. **Rail links to `.eu`-redirected routes.** `seo-rail.tsx:87-91` — described in item 14.

Nothing found that touches the locked constraints: no invented crawler-only facts, no stripped pre-render facts, no unsubstantiated "best" claims, no rewritten disclosures, and the three deliberately-open decisions (company h1 disagreement, insider names out of sector pre-renders, `TODO(us-reports)` currency hardcodes — `report.tsx:442-446`, `functions/reports/index.js:41-42`) are all still carrying their comments.
